# Integrations

NextTabletDriver can share live pen data with other programs in two ways:

| | WebSocket server | SDK |
| --- | --- | --- |
| Good for | Stream overlays, web pages, small scripts | Games and tools that want to embed the driver |
| Needs the desktop app | Yes | No |
| Languages | Anything that can open a WebSocket | C, C++, C#, and anything that can call a C library |
| Data | Raw sensor position, pressure, status | Position (0 to 1), pressure, tilt, buttons, device info |

## WebSocket

The desktop app has a small WebSocket server. A WebSocket is a long-lived connection that lets a program receive a stream of messages. It is **off by default**.

### Turn it on

Open **Settings → WebSocket Server** and tick **Enable WebSocket Server**.

| Setting | Default | Meaning |
| --- | --- | --- |
| Port | 8080 | The TCP port to listen on. Change it if another program uses it. |
| Rate | 60 Hz | How many messages per second each client receives. |
| Payload: Coords, Pressure, Status | On | Which values are included. |
| Payload: Tilt | On | Has no effect: tilt is not sent. |

### Who can connect

- The server listens on `127.0.0.1`, so only programs on **your own PC** can reach it. Other computers cannot.
- A web page can connect only if it comes from `localhost`, `127.0.0.1` or `[::1]`, or if it is a local file (for example a browser source in OBS). A normal website on the internet is refused, even if you have it open.
- Programs that are not web browsers (scripts, apps) can always connect.
- At most 10 clients can be connected at once.

### The messages

While at least one client is connected, the server sends the latest pen data to every client, `Rate` times per second. Each message is a text frame with a JSON object:

```json
{ "x": 15234, "y": 8120, "pressure": 1840, "status": "Contact", "is_connected": true }
```

| Field | Type | Meaning |
| --- | --- | --- |
| `x`, `y` | integer | Position in the **raw units** of the tablet sensor, not millimeters or pixels. Divide by the tablet's maximum X and Y (`MaxX` and `MaxY` in its definition) to get a position from 0 to 1. |
| `pressure` | integer | Raw pressure, from 0 up to the maximum pressure of the tablet. |
| `status` | text | One of `Disconnected`, `Out of Range`, `Hover`, `Contact`, `Active`, `Eraser`, `Pen`, `Touch`, `Aux`, `Rotation`, `Tool`, `Mouse`. `Contact` means the tip touches the surface. |
| `is_connected` | boolean | `true` when the tablet reports a pen. |

`x` and `y` are left out when **Coords** is off, `pressure` when **Pressure** is off, and `status` and `is_connected` when **Status** is off. The server sends the most recent data at a fixed rate, so it does not send every single packet. Anything a client sends to the server is ignored.

### Example: a web page

```html
<script>
  const socket = new WebSocket("ws://127.0.0.1:8080");
  socket.onmessage = (event) => {
    const pen = JSON.parse(event.data);
    console.log(pen.x, pen.y, pen.pressure, pen.status);
  };
</script>
```

### Example: Python

This uses the [`websockets`](https://pypi.org/project/websockets/) package (`pip install websockets`).

```python
import asyncio
import json

import websockets


async def main():
    async with websockets.connect("ws://127.0.0.1:8080") as socket:
        async for message in socket:
            pen = json.loads(message)
            print(pen)


asyncio.run(main())
```

## SDK

The SDK is a library, `ntd_sdk`, that runs the NextTabletDriver engine **inside your program**. Your game or tool then reads the tablet itself. The desktop app does not have to be installed or running.

The SDK does **not** move the operating system cursor. It only gives you the pen data. You decide what to do with it. Because of that, you also get pressure and tilt on Windows.

This page is about *embedding* the engine. If you want to change pen data inside NextTabletDriver instead (for example to smooth it), write a *plugin*: see [Plugin development](plugin-development.md). The SDK loads approved plugins too, but it starts with default settings and cannot enable them, so they do nothing in your program.

### Build it

From the root of the repository:

```bash
cargo build --release --manifest-path sdk/Cargo.toml
```

The build creates:

| Output | Where |
| --- | --- |
| The library | `sdk/target/release/ntd_sdk.dll` (Windows, with an import library `ntd_sdk.dll.lib`) or `libntd_sdk.so` (Linux). A static library is also built. |
| The C header | `sdk/include/ntd_sdk.h` |
| The C# declarations | `sdk/bindings/csharp/NextTabletDriver.Sdk/NativeMethods.g.cs` |

The header and the C# file are generated by the build. Do not edit them by hand. The SDK has its own version number (see `sdk/Cargo.toml`) and its own interface version, `NTD_SDK_ABI_VERSION`, which changes only when the C interface changes in a way that breaks existing programs.

### One owner per tablet

Only one program can open a tablet. If several programs use the SDK, or the desktop app is also running, the first one to start becomes the **owner**. The others become **readers**: they receive a copy of the owner's data. When a reader changes the mode or the active area, the request goes to the owner. If the owner closes, a reader takes over. See [Architecture](architecture.md#one-owner-per-tablet).

On Linux the SDK still needs the [udev rules](linux.md) to open the tablet.

### The C interface

| Function | What it does |
| --- | --- |
| `ntd_sdk_abi_version()` | Returns the interface version of the library. Compare it with `NTD_SDK_ABI_VERSION` from the header you built against. |
| `ntd_init()` | Starts the engine in a background thread. Calling it again is harmless. |
| `ntd_shutdown()` | Stops the engine. Safe to call even if `ntd_init` was not called. |
| `ntd_poll_state(&state)` | Copies the latest pen data and settings into a `NtdState`. |
| `ntd_set_mode(mode)` | `0` for absolute, `1` for relative. |
| `ntd_set_active_area(x, y, w, h, rotation)` | Sets the active area in millimeters. X and Y are the center of the area. The engine keeps it inside the tablet surface. |

Every function that can fail returns `NTD_OK` (0) or a negative error code:

| Code | Meaning |
| --- | --- |
| `NTD_ERR_HID_INIT_FAILED` (-1) | The HID system could not start (missing permission, no backend). |
| `NTD_ERR_NOT_INITIALIZED` (-2) | `ntd_init` was not called, or `ntd_shutdown` already ran. |
| `NTD_ERR_NULL_POINTER` (-3) | You passed a null pointer. |
| `NTD_ERR_INVALID_ARGUMENT` (-4) | A value was out of range, for example an unknown mode. |
| `NTD_ERR_COMMAND_FAILED` (-5) | The owner could not be reached. |
| `NTD_ERR_PANIC` (-6) | An internal error was caught. It never crosses into your program. |

### `NtdState`

| Field | Meaning |
| --- | --- |
| `is_connected` | A pen is detected. This is **not** the same as "a tablet is plugged in". |
| `status` | `0` no supported tablet found, `1` out of range (the tablet is open but no pen is near), `2` hover, `3` contact, `4` active, `5` eraser, `6` pen, `7` touch, `8` aux, `9` rotation, `10` tool, `11` mouse. |
| `u`, `v` | Position inside the active area, from 0 to 1. |
| `screen_x`, `screen_y` | Position on screen in pixels (absolute mode) or movement since the last packet (relative mode). The SDK cannot set a target area and assumes 1920 × 1080, so for the real screen use `u` and `v` and scale them yourself. |
| `pressure` | From 0 to 8191. |
| `tilt_x`, `tilt_y` | Tilt in degrees. |
| `buttons`, `eraser` | Pen button bits, and whether the eraser end is used. |
| `is_down` | The tip counts as touching. |
| `device_name`, `device_name_len`, `vid`, `pid` | Name (UTF-8 bytes, up to 64) and USB ID of the tablet. |
| `mode` | The current mode, `0` or `1`. |
| `active_area_x`, `_y`, `_w`, `_h`, `_rotation` | The current active area. |
| `config_version` | Increases every time the settings change. |

### Example in C

```c
#include <stdio.h>
#include "ntd_sdk.h"

int main(void) {
    if (ntd_init() != NTD_OK) return 1;

    ntd_set_mode(0);                                   // absolute
    ntd_set_active_area(80.0f, 70.0f, 76.51f, 51.5f, 0.0f);

    struct NtdState state;
    if (ntd_poll_state(&state) == NTD_OK && state.is_connected) {
        printf("u=%.3f v=%.3f pressure=%d\n", state.u, state.v, state.pressure);
    }

    ntd_shutdown();
    return 0;
}
```

A complete program with a loop is in [`sdk/examples/c_consumer`](../sdk/examples/c_consumer/README.md).

### Example in C#

The project `sdk/bindings/csharp/NextTabletDriver.Sdk` wraps the native library in a class called `NtdClient`. Create **one** client for the whole process and dispose it when you are done. The native library must be next to your program.

```csharp
using System;
using NextTabletDriver.Sdk;

using var client = new NtdClient();
client.SetMode(DriverMode.Absolute);
client.SetActiveArea(80f, 70f, 76.51f, 51.5f, 0f);

var state = client.PollState();
if (state.IsConnected)
    Console.WriteLine($"u={state.U:F3} v={state.V:F3} pressure={state.Pressure}");
```

A complete program is in [`sdk/examples/csharp_console`](../sdk/examples/csharp_console/README.md).
